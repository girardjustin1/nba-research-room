# Independent audit, round 3: X injury-news pipeline

Audit date: 2026-10-08. Scope: this checkout, offline. **Every post in the audit fixtures is invented. None describes an actual injury, announcement, or reporter statement.** Fictional handles are used throughout. Player membership and game IDs come from the supplied database; they are fixture context, not independently verified current rosters.

Read the October 5 and October 8 reports in `docs/audits/`, including their fix notices. This report does not re-report B06's first-tip cutoff or B10's original missing-game-date defect: those fixes exist. X05 identifies a remaining, narrower fallback problem in the new targeting logic.

**CONFIRMED** means reproduced with assertions, a database query, or the labeled downstream run. **SUSPECTED** means a reasoned risk whose model/live effect was not reproduced. Reproductions establish mechanisms, not their frequency in production. No model or X API was called. Only `.venv/bin/python` was used. The source database was opened read-only; mutations used in-memory stores. Every written file is under `audit/`.

## 1. Summary

1. **The read budget is not a hard cap across failures.** A successful first query followed by a failed second query loses all accounting. The reproduction returns 41 posts against a 30-post daily limit. Three failed parser runs return 30 posts against a limit of 10, with zero reads logged.
2. **Useful news can disappear before the model sees it.** There is no pagination; advancing the newest timestamp strands unread older posts. The scheduler and 90-minute lookback miss morning/overnight news, team accounts disappear on off days, and the keyword filter rejects clear statements such as “will sit,” “day-to-day,” and “good to go.”
3. **An absence can reappear after the player returns.** Return cancellation depends on the requested output date range. A return on October 26 ends the absence in a wide query, but an October 27 query resurrects it. Separately, a lower-authority update that loses today's precedence contest can still erase the future absence.
4. **Current news grading does not measure the actual X decisions reliably.** It grades the newest X post, while projections choose authority before recency; it ignores carried absences and game IDs, merges accounts into `x`, and can grade news first ingested after tip. Its displayed played/listed rates are insufficient evidence for trusting the deployed overrides.
5. **Even perfect extraction does not guarantee delivery.** The final set has 60 posts, 59 events, and nine no-event posts. **52/59** labeled events reach the correct game and probability in isolated downstream fixtures; **51/57** on the subset compatible with the current one-event-per-player prompt. Two misses are intentional safe name quarantine, not unsafe guessing. Real parser accuracy remains unmeasured.

### Precedence and time-frame policy reviewed

The implemented order is **non-carried before carried**, then **manual → official X → insider X → NBA report → beat X → aggregator X → BDL**, then latest timestamp within that rank. A tomorrow-targeted X event is non-carried on its target date even if posted yesterday. BDL is always carried. This explains why a fresh BDL row can lose to older X; it is the documented policy, not a newly discovered ordering implementation bug.

The controls confirm manual wins and keeps its cap, beat X beats BDL, and newest same-rank news wins. The team's earlier Questionable beats a later beat writer's Probable, and even a newer NBA Available. Authority has no freshness expiry for that target game. That may be an intentional conservative choice, but it does not demonstrate that X is more accurate: the configured Questionable/Doubtful/Probable probabilities were fitted to NBA reports, not to X by tier or lead time. Day-To-Day is assumed, Available is 1.0, and the return ramp is an assumption. No X outcome data here can validate those choices.

For Out with a lower/upper duration, zero probability lasts for the lower bound, then the code ramps through the upper bound. A minimum-only duration has no ramp and no row after the minimum; that is a fallback to the baseline, **not confirmation of return**. Durations are floored to integer calendar days and capped at 60 in the config model default. Out For Season expands to the caller's end date rather than a separately stored season end. Absence dates start from the post's Eastern calendar date, clipped to start at the targeted game. If the next game is after the entire duration, `... or [(d0, 0.0)]` still invents an Out for that game; X05 reproduces this with an exact one-day absence on an off day.

`starting` survives ingestion but does not flow into resolved overrides. A lineup extraction can still matter if it is labeled Available. Available/Probable without a numeric cap generate no limiting-status alert; a numeric cap does. Corrections within one same-rank source work by timestamp. Cross-source corrections obey authority first, not a generic latest-news rule.

### What would be good enough to act on X first

For this small, hand-authored challenge set, require **zero false injury/availability events, zero wrong-player or wrong-game events, and correct critical Out/Available reversals**. Require exact dates, bounds, starting flags, and numeric caps wherever explicit. I would expect all 57 current-contract gold events to be extractable under a clarified contract; at minimum, any miss must be an explicit abstention that remains nonactionable, not a silently fabricated substitute. Fix the confirmed downstream defects first: parser scores cannot compensate for a missing post or a revived absence.

This set alone cannot establish a safe live error rate. There are only nine negatives, and the set deliberately overrepresents edge cases. Even zero failures among 60 independent examples leaves an approximately 4.9% one-sided 95% upper error bound; zero among nine negatives leaves about 28%. The fixtures are not even a random independent production sample. A reasonable deployment target is **at least 99% precision on actionable player/game/status claims**, no critical date/identity failures, and **at least 95% recall** on clear factual announcements, measured prospectively by source tier and lead time. About 300 independent cases with zero errors are needed just to put a one-sided 95% upper error bound near 1%; meaningful subgroups need their own evidence.

Begin with explicit official-team/national-source rulings, exact resolved identity and game, bounded freshness, and abstention on conflict. Beat/aggregator corrections and inferred return probabilities need separate validation. Preserve privacy-compatible derived event/decision provenance and first-seen times, then compare decisions at equal deadlines against game outcomes and later NBA reports. Track event precision/recall, wrong-game errors, coverage gaps, alert reversals, and probability calibration. “A forced tool call succeeded” and “the source's players often played” are not enough to promote X over the official report.
